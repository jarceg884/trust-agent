# Fix t_dd2f5f65 — race multi-proceso del auto-enroll (410s mutuos)

Hallazgo: docs/hermes-download.md §4.1 (E2E spec 023, 03-plugin-log.txt).
Fix: `enroll.py` (plugin trust-agent-governance, spec 022) — sin cambios de
contrato server-side.

## Qué se cambió

1. **flock por home** (`enroll.py::_HomeLock`): lock exclusivo sobre
   `$HERMES_HOME/trust-agent/.autoenroll.lock` (LOCK_EX con espera acotada
   `AUTOENROLL_LOCK_WAIT_S=30s`; el kernel lo libera si el proceso muere).
   Serializa el enroll ENTRE PROCESOS del mismo home: gateway standalone +
   TUI + gateways explícitos. Aplica al watcher zero-UI (`auto_enroll_once`)
   Y al comando manual `/trust-enroll` (no pueden pisarse entre sí).
2. **Reuse-first** (`enroll.py::_enroll_attempt`): si hay un enrollment
   token guardado para la MISMA org, se canjea SIN re-POSTear
   `/api/devices/enroll` — cada POST resetea `enrollment_token_hash` del
   device pending (upsert por fingerprint, `devices/service.py::enroll`) e
   invalida el token que otro proceso poll-ea. Solo se re-POSTea si el token
   guardado responde 410 (consumido/caducado/rechazado → recovery con
   re-enroll, ADR-013); un error transitorio del canje NO re-POSTea.
3. `_exchange_saved` → `_exchange_saved_raw` (outcomes crudos); el path 409
   conserva el mensaje "ask an admin to revoke".
